# 规格：GFM 渲染、CodeMirror 编辑器、内嵌图片与可安装 PWA

## 问题陈述

我在 NAS 上运行这个 Memos 分支，并通过其 Web UI 使用。有几件事妨碍了我：

1. **表格会坏。** 当单元格包含转义竖线（`\|`）、含 `|` 的行内代码或链接、空单元格、两侧无空格的单元格、列数不一致的行、无首尾竖线的行，或 `<br>` 之类的 HTML 时，GFM 表格就不再渲染，变成纯文本。列对齐（`:--`、`:-:`、`--:`）被忽略。我无法确信写下的内容会正确显示。
2. **写 Markdown 太简陋。** 编辑器只是一个纯文本框：没有语法高亮、没有预览、没有表格辅助，几乎没有格式按钮。我写的 Memo 篇幅长、结构化，需要一个真正的 Markdown 编辑器。
3. **粘贴的图片位置不对。** 粘贴截图时，它被作为文件添加到 Memo 下方，而不是出现在光标处。我希望图片位于我正在写的段落之中。
4. **没有桌面应用。** 我想从 macOS Dock 以独立窗口打开 Memos，而不是去找浏览器标签页。

## 解决方案

- Memo 正文在浏览器中由符合标准的 GFM 渲染器渲染，因此表格、转义、对齐和安全 HTML 的表现与 GitHub 一致。所有 Memos 专有语法继续可用，旧 Memo 显示效果相同或更好（ADR 0001）。
- 编辑器改为源码模式 Markdown 编辑器，具备语法高亮、格式栏、表格辅助、斜杠命令和编辑/预览切换。输入的文本按原样保存。
- 粘贴或拖放图片时，将其作为内嵌图片插入 Memo 正文的光标处。内嵌图片仍属于该 Memo：与其共享可见性、随其一同删除，且不在附件列表中重复显示。从文本中移除图片并保存即删除该图片（ADR 0002）。
- Memos 成为可安装的 PWA，具备完整 manifest、缓存的应用外壳、更新提示，以及一个寓意快速捕捉思绪碎片的紫色新 Logo。

## 实现决定

### 渲染（ADR 0001）

- **唯一事实来源。** Memo 正文（`memo.content`）是渲染的唯一输入。浏览器用 unified/remark 加 remark-gfm 和 remark-math 解析它，转换为 hast 树，用白名单 schema 净化 HTML，再将结果映射为 React 组件。
- **Memos 语法插件。** Memos 专有语法实现为 micromark/mdast 扩展，产出自定义节点类型，每种由各自的组件渲染。覆盖的语法：标签、嵌入 Memo、嵌入资源、引用 Memo、高亮、剧透、上标、下标。Mermaid 和 `__html` 仍作为代码块语言。
- **`__html` 例外。** ```` ```__html ```` 块保持当前不净化的行为。这是净化 schema 的明确例外。
- **单一渲染器。** MemoContent 组件保持其公共职责：渲染 Memo，带折叠、图片分组和图片查看器。其输入从服务端节点改为 Memo 正文字符串。所有调用方切换到新输入：Memo 视图、归档 Memo、回顾卡片、嵌入 Memo、导出模板和编辑器预览。
- **移除项。** 从 Memo API 响应中移除 `nodes` 字段，服务端不再为每次响应解析 Memo 正文。浏览器不再调用 Markdown 服务的 restore-nodes 方法。删除变为死代码的基于节点的渲染组件。Markdown 服务 RPC 仅在仍有其他用途时保留；否则连同生成的客户端一起移除。
- **任务切换。** 一个纯函数接收 Memo 正文、任务标记的源码偏移（来自 mdast position）和新的勾选状态，返回新的 Memo 正文。只改变 `[ ]`/`[x]` 字符。结果通过现有 UpdateMemo 调用保存。
- **标签规则。** remark 标签插件严格遵循 gomark 的标签规则：允许的字符、终止符，以及在代码、链接和标题中的排除。两端针对同一份共享 fixture 运行（见测试）。
- **服务端对 gomark 的使用。** 服务端保留 gomark 用于标签提取、payload 属性（has link、has code、has image、has incomplete tasks、references）、摘要和 RSS。当 Memo 正文引用图片时，has-image 属性也必须为 true。
- **图片。** 图片组件在现有图片查看器中按原始宽高比渲染，`max-width: 100%`，最大高度约 60vh。它懒加载，并在源为 Memos 资源 URL 且图片位于网格中时显示缩略图 URL。
- **表格。** 表格组件应用 GFM 列对齐，并在表格宽于正文时水平滚动。
- **净化白名单。** schema 保留标准 GFM 元素、`details`/`summary`/`kbd`/`sub`/`sup`/`br`/`mark`、安全属性，且只允许 `http`/`https`/`mailto`/相对 URL。去除 `script`/`style`/`iframe`、所有 `on*` 属性以及 `javascript:`/`data:` URL（现有行为已允许的图片除外）。

### 编辑器

- **引擎。** 用 CodeMirror 6 替换 textarea，配合 `@codemirror/lang-markdown`（GFM）、代码块嵌套语言高亮、历史记录、输入法安全输入，以及浅色和深色模式下的现有主题颜色。
- **命令式 API。** 编辑器保留与当前等价的命令式 ref API：插入文本、获取或设置内容、选区和光标、聚焦、滚动到光标。现有调用方（TagSelector、关联弹层、位置、草稿缓存、禅模式）继续工作，行为不变。
- **命令。** 编辑器命令是基于 `EditorState`/事务的纯 CodeMirror 命令，与 React 无关：
  - 格式：包裹或切换粗体/斜体/删除线/代码/链接，切换标题级别，切换列表/任务/引用
  - 表格：插入表格（行 × 列）、下一个/上一个单元格、在最后一行按 Enter 添加行、格式化表格、转义单元格中的 `|`
  - 斜杠菜单：仅在行首或空白后触发；筛选；插入块
  - 列表延续和 Tab 缩进
  - Markdown 快捷键 Cmd/Ctrl+B/I/K，遵守禁用它们的工作区设置
  - 保存和禅模式切换
- **建议。** `#` 标签和 `@` Memo 建议迁移为 CodeMirror 自动补全源，产生与当前相同的插入内容（例如 `![[memos/uid]]`）。
- **格式栏。** 在编辑器获得焦点时渲染于其上方，禅模式下始终显示。包含格式按钮、插入表格、插入数学公式和编辑/预览分段切换。预览用 MemoContent 渲染当前文本。
- **i18n。** 新的 UI 字符串添加到 en、zh-Hans、zh-Hant 和 ja 语言包。

### 内嵌图片（ADR 0002）

- **粘贴与拖放。** 一个纯决策函数对粘贴或拖放事件分类：
  - 剪贴板有非空文本 → 粘贴文本（默认行为）
  - 否则，图片文件 → 内嵌图片上传
  - 其他文件 → 附件上传
  
  工具栏上传始终产生附件。斜杠菜单的「上传图片」产生内嵌图片。
- **上传流程。** 对每张内嵌图片：
  1. 在光标或拖放位置插入唯一占位符 `![Uploading…](memos-upload://<token>)`。
  2. 用现有 CreateResource API 上传。粘贴的文件重命名为 `pasted-YYYYMMDD-HHmmss.<ext>`；拖放的文件保留原名。
  3. 按 token 将占位符（其位置随编辑跟踪）替换为 `![](/file/resources/{id}/{filename})`，失败时移除并显示 toast。
  
  每个上传的资源都记录到编辑会话的「本次会话上传」集合中。
- **引用解析。** 一个纯函数基于 remark 解析从 Memo 正文中提取资源引用。它识别：
  - 形如 `/file/resources/{id}/…` 的图片或链接 URL
  - 当前源的 `{origin}/file/resources/{id}/…`
  - `![[resources/uid]]`
- **保存协调。** 一个纯函数计算需要关联和需要删除的内容。这是 S3 接缝：

  ```ts
  // 决策结构，源自设计讨论。
  interface ReconcileInput {
    original: { content: string; resources: Resource[] }; // 编辑器打开时的状态（新 Memo 为空）
    current: { content: string; attachments: Resource[] }; // 用户编辑后的附件列表
    uploadedThisSession: Resource[];
    origin: string;
  }
  interface ReconcileOutput {
    linkToMemo: Resource[];     // 保存时作为 Memo 的 resources 发送
    deleteUnused: Resource[];   // 不属于任何 Memo 且不再被引用的上传
  }
  ```

  规则：
  - 在 `current.content` 中被引用、且属于本 Memo、或未使用、或在本次会话上传的资源，予以关联。
  - `current.attachments` 中的附件予以关联。
  - 属于其他 Memo 的资源永不关联；它保持为引用。
  - 曾在 `original.content` 中被引用或在本次会话上传、现已不再被引用且不在附件列表中的资源，不予关联：
    - 若它曾属于本 Memo，由服务端现有的 SetMemoResources 语义删除；
    - 若它仍未使用，放入 `deleteUnused`，由客户端删除。
  - 编辑器打开时为附件的任何资源保持为附件，除非用户将其从列表中移除。
- **取消。** 取消编辑现有 Memo 时，删除「本次会话上传」中所有仍未使用的资源。新 Memo 草稿保留其上传。被放弃的上传在现有资源页面中显示为未使用资源。
- **服务端。** 无数据库 schema 变更、无迁移（因此 migration-repair 脚本无需改动）。SetMemoResources 语义不变。资源二进制的可见性检查仍基于资源自身所属的 Memo。
- **显示。** Memo 视图的附件列表只显示附件：即 Memo 的资源减去其 Memo 正文中引用的资源，由同一引用解析器计算。编辑器的附件列表遵循相同规则。

### PWA 与 Logo

- **插件。** 以 prompt 模式添加 vite-plugin-pwa，用 Workbox 预缓存构建出的应用外壳。
- **仅网络路由。** 以下路由永不被 service worker 缓存：`/api/`、`/memos.api.v1.`、`/file/`、RSS 路由以及服务端渲染路由。
- **导航回退。** 导航回退到缓存的 `index.html`，使 SPA 离线时也能加载并显示其现有的网络错误状态。
- **Manifest。**
  - `id`、`start_url`（`/`）和 `scope`（`/`）
  - name 和 short_name 为 "Memos"，以及一段描述
  - `display: standalone`
  - `background_color`，以及设为浅色主题值的 `theme_color`
  - 192/512 图标，purpose 为 `any` 和 `maskable`
  
  manifest 由插件生成，移除旧的静态 webmanifest。
- **主题色。** 保留现有浅色和深色 `theme-color` meta 标签，应用使其与当前主题保持同步，使独立窗口标题栏跟随浅色/深色。添加 `apple-mobile-web-app-title` 及相关 Safari meta 标签。
- **更新提示。** service worker 有等待中的更新时，显示一个小的「有新版本可用，点击刷新」toast。它从不自行重新加载。其字符串加入四个语言包。
- **服务端缓存。** 前端服务器必须以 no-cache 头提供 service worker 文件和 manifest，以便检测到更新。带哈希的资源文件保持 immutable 缓存。
- **Logo。** 紫色渐变 #8B5CF6 → #6D28D9，白色卡片形状，暖黄色 #FBBF24 点缀。
  1. 产出三个完成的 SVG 方案：A 闪卡，B 聚拢碎片，C 碎片组成 M。
  2. 在浅色和深色 Dock 模拟背景上以 512/128/32/16 px 渲染每个方案，并呈现供选择。
  3. 用户选定后，由所选 SVG 生成所有位图资源（favicon、apple-touch-icon、192/512 any 和 maskable、UI 中使用的 logo 和 full-logo），并全站替换。
  
  应用名保持 "Memos"。

### 交付

- **阶段。** 一个新分支，按顺序分三个阶段，每个阶段在真实浏览器中验证后再进行下一个：① 渲染器，② 编辑器与内嵌图片，③ PWA 与 Logo。
- **分支名。** 使用 `feat/` 前缀，不要用 `claude/` 或 `chriscurry/`。推送这两个前缀的分支会触发 auto-merge-staging 工作流，把分支合并进 staging。
- **在 macOS 开发机上做的事（开发与验证）。**
  - 编辑代码。
  - 用 `pnpm dev` 和 air 热重载在浏览器中验证功能。
  - 运行 vitest、`go test ./...`，以及 `cd web && pnpm lint --fix`（每次提交前都要运行）。
  - 更新 CHANGELOG.md 和 CHANGELOG_zh.md。
  - 开发机上不运行 `pnpm release`，不编译正式二进制，也不运行 `docker build`。
- **代码同步。** 三个阶段全部完成后，把功能分支一次性推送到 `origin`（https://github.com/flyflypeng/memos），构建机从那里拉取。
  - 本地 `main` 领先 `origin/main` 57 个提交，可以快进；功能分支从本地 `main` 创建。
  - 不打 tag。打 `v*` tag 会触发 docker-build 工作流，它会向 Docker Hub 的 `chriscurrycc/memos` 推送镜像。
- **在构建机上做的事（编译与镜像构建）。** 构建机为用户的 shanghai-ali-ecs-64c（x86_64，64 核，Docker 29 + buildx，免密 sudo；Docker 守护进程和 git 访问 GitHub 都要经过内网 HTTP 代理）。
  1. 把功能分支克隆或更新到构建机上的独立目录，然后 checkout 功能分支。
  2. 执行 `sudo docker build`，通过 `--build-arg` 传入代理变量，构建 linux/amd64 镜像，标签为 `ghcr.io/flyflypeng/memos:<短提交哈希>`，并带上 `org.opencontainers.image.source` 标签。Dockerfile 已经包含前端构建和 Go 编译两个阶段。
  3. 在构建机上用临时端口和临时数据目录启动镜像做冒烟测试，测完删除容器和数据。
  4. 推送到 ghcr.io 私有仓库。token 取自本机 `gh auth token`（需要 `write:packages` 权限），经 SSH 标准输入传给 `docker login --password-stdin`，使用临时 `DOCKER_CONFIG` 目录，推送后立即删除。token 不能出现在命令参数、日志或仓库中。另外打一个可移动标签 `feat-markdown-editor`。
- **切换线上容器。** 现有服务由 NAS 上的 Compose 文件运行，使用 `chriscurrycc/memos:latest` 镜像，并挂载生产数据目录。
  - 切换前备份 Compose 文件和 `memos_prod.db`。
  - NAS 用只读的 `read:packages` token 登录 ghcr.io 拉取镜像。
  - 把 Compose 中的镜像改为 `ghcr.io/flyflypeng/memos:<短提交哈希>`，然后重建容器。
  - 这些操作需要 sudo，由用户在自己的终端中执行，并且只有在用户明确确认后才执行。本次改动不涉及数据库迁移。
  - NAS 的连接方式见用户全局记忆和 PersonalWorkflow 运行手册。主机名、端口和用户名不要写进本仓库，因为本仓库会被推送到公开的 GitHub。
- **最终检查。**
  - 构建机上 `docker build` 成功，冒烟测试通过，镜像已推送到 ghcr.io。
  - 切换镜像后，通过现有 HTTPS 域名完成人工验收。

## 测试决定

- **什么是好的测试。** 通过模块的公共输入驱动它，断言使用方可见的输出（渲染的 DOM、结果文档文本、协调决策、提取的标签集合）。从不断言内部节点类型、插件接线、调用次数或源码文本，也从不锁定偶然的措辞。测试是确定性的，与网络和时间隔离；为粘贴文件名注入时钟。
- **框架。** 前端目前没有测试框架。在 `web/` 中添加 vitest、jsdom 和 @testing-library/react，并添加 `test` 脚本。
- **S1 渲染。** 输入：Memo 正文字符串。断言：MemoContent 渲染的 DOM。用例：
  - 表格 fixture 集：转义竖线、行内代码中的竖线、链接中的竖线、无填充单元格、空单元格、参差行、无外侧竖线、单元格中的 `<br>`、对齐、CJK 标点、emoji
  - 每种 Memos 专有语法，以及必须不匹配的用例（代码中的标签、URL 片段、标题）
  - 净化：移除 script、`on*` 和 `javascript:`；保留允许的 HTML；`__html` 例外
  - 任务切换：点击复选框产生的新 Memo 正文仅在该任务标记处不同，包括嵌套、引用和表格之后的用例
  - 附件列表排除被引用的资源
- **S2 编辑器命令。** 无头 `EditorState` 加一个命令产生新文档和选区，不涉及 React。用例：
  - 粘贴/拖放分类（文本优先、图片、其他文件）
  - 占位符插入、在中间编辑后按 token 替换，以及失败时移除
  - 粘贴文件名格式
  - 表格插入、单元格导航、添加行、格式化和竖线转义
  - 斜杠触发规则（行首或空格后，不在 URL 或 "1/2" 中）及插入
  - 格式包裹和切换
  - 列表延续
- **S3 保存协调。** 上述纯协调函数，基于场景表：
  - 带粘贴的新 Memo
  - 移除引用：被删除
  - 移除对已有附件的引用：保持为附件
  - 引用附件：变为内嵌图片
  - 跨 Memo 引用：不受影响
  - 同源绝对 URL、其他源 URL 和 `![[resources/uid]]`
  - 取消时的清理集合
- **S4 标签一致性。** 在仓库中立位置放一份共享 JSON fixture，包含 `{content, tags}` 用例。一个 Go 测试对其运行 gomark 标签提取，一个 vitest 测试对其运行 remark 标签插件。两者必须产出完全相同的标签集合。
- **服务端测试。** 更新任何依赖已移除 `nodes` 字段的 API 测试。仅为 has-image payload 变更添加 Go 测试，风格与现有 API 和 store 测试一致。
- **已有先例。** Go：API 和 store 测试套件使用真实 SQLite store 和 testify `require`。前端没有先例；vitest 约定由本次工作建立。
- **人工验收（不自动化）。**
  - PWA：在 NAS 上构建的镜像上线后，通过现有 HTTPS 域名验收（开发机的 localhost 只用于开发期间的预检）。检查项：Chrome 可以安装；窗口为独立模式；标题栏跟随浅色和深色主题；部署新构建后出现刷新提示；API 和文件响应从不来自 service worker 缓存。
  - Safari：添加到程序坞显示正确的名称和图标。
  - Logo：三个方案已评审；所选方案在 Dock、favicon、登录页和侧边栏中可见。
  - 编辑器：中文输入法在 macOS Chrome 和 Safari 中可用。
  - 手机：冒烟检查可以输入并保存 Memo。

## 不在范围内

- 与上游（chriscurrycc/memos 或 usememos/memos）同步，以及读取 `memo.nodes` 的第三方客户端。
- RSS 输出。它保留 gomark HTML 渲染器及其表格限制。
- 替换 gomark 或在服务端采用 goldmark。
- WYSIWYG 或 Typora 式实时渲染、并排预览和 Vim 模式。
- 离线阅读或编写 Memo、后台同步、徽标、Dock 快捷菜单和 window-controls overlay。
- 将移动端编辑器打磨到「可用」以上。
- 自动清理未使用资源，以及复制跨 Memo 资源。
- 更改资源可见性规则或数据库 schema。
- 重命名应用。
- 发布到镜像仓库（registry）、打 tag，以及推送到 `origin` 功能分支以外的任何远端或分支。

## 补充说明

- **需遵守的文档。** ADR 0001（客户端渲染）和 ADR 0002（由 Memo 正文推导内嵌图片与附件）。术语遵循 glossary：Memo、Memo 正文、资源、内嵌图片、附件、未使用资源。
- **设计时未验证。** `![[resources/uid]]` 目前很可能总是显示 "Resource not found"：该组件用 UID 按 name 查找资源。新的嵌入资源组件必须按 UID 解析。
- **安全考量。** 不属于任何 Memo 的资源任何持有 URL 的人都可读取，且 id 是顺序的。这就是内嵌图片必须关联到其 Memo、会话上传必须在取消时清理的原因。
- **预期的重复。** 标签检测现在同时存在于 Go 和 TypeScript 中。S4 fixture 是防止两者偏离的唯一保障；任一端修复标签 bug 时都要扩充它。
- **部署。** 开发和验证在 macOS 开发机上进行。编译和容器镜像构建在 NAS 上进行：NAS 从 `origin` 拉取功能分支后执行 `docker build`。服务位于现有 HTTPS 域名之后，PWA 依赖这个安全上下文。
